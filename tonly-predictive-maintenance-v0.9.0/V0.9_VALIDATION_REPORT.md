## Smoke test against the previously supplied charging log

The source log was parsed again (4,254 rows; 3,975 initially clean, 274 review, 5 rejected; 44 distinct raw IDs). The ML pipeline identified **54 implausible usage-rate jumps** that the original first-pass row audit did not detect. The training set after robust filtering contained 191 next-interval examples, with 152 training examples and 39 chronological holdout examples (validation began 2026-09-12).

| Method | Holdout MAE (km/day) | Median baseline MAE (km/day) | Beats baseline? |
|---|---:|---:|---|
| Median-rate baseline | 101.0654 | 101.0654 | Reference |
| Random Forest | 105.8951 | 101.0654 | No |
| XGBoost | 111.2713 | 101.0654 | No |
| Hybrid median | 106.5232 | 101.0654 | No |

**Operational consequence:** with this supplied dataset, the UI should display the RF/XGBoost comparison but keep the ML choices disabled because neither model beats the baseline on the chronological holdout. Also, if a selected truck's latest source reading is an implausible jump, forecasting is blocked until the reading is reviewed. This is deliberate; the app must not present a worse or corrupted-data model as an improved prediction.
