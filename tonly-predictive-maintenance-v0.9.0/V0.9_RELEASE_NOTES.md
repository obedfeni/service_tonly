# v0.9.0 release notes

## Added
- Authenticated Next.js proxy route `/api/ml/forecast` for the separately deployed Python ML service.
- FastAPI service using real scikit-learn `RandomForestRegressor` and XGBoost `XGBRegressor` models.
- Models predict next observed odometer usage rate (km/day) from past usage intervals; they do not predict component failures.
- Chronological holdout evaluation with MAE reported against a median-rate baseline.
- Rule-based, Random Forest, XGBoost and hybrid median usage-rate forecasts in the existing Predictive Intelligence UI.
- Persistent `ml_model_runs` audit records via migration 005.
- Server-side validation that the selected ML run matches the truck, PM type, service baseline, odometer snapshot, source name, row count and source fingerprint before saving an ML-based forecast.
- Render Docker Blueprint and deployment documentation for the Python service.

## Maintained safeguards
- Existing approved PM thresholds: PM1 5,000 km, PM2 15,000 km, PM3 25,000 km, then +10,000 km.
- Calendar intervals are entered from approved maintenance documentation; no default is invented.
- Imported source readings remain review-only.
- Insufficient training data produces an explicit status instead of synthetic model predictions.
- Robust past-only odometer-rate outlier filtering prevents implausible jumps from contaminating features; a suspicious latest reading blocks the forecast until reviewed.
- RF/XGBoost/hybrid methods are selectable for saving only when their chronological holdout MAE beats the median-rate baseline.
- The Python API requires a server-only Bearer secret.
